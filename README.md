# Print Round Robin

Графический балансировщик печати для Windows 10/11 на Python и Tkinter. Приложение создаёт одну виртуальную очередь Windows и отправляет **целые задания печати** на несколько одинаковых сетевых принтеров по RAW TCP (обычно порт `9100`) по схеме Round Robin.

## Возможности

- Единый Tkinter-интерфейс: мониторинг, управление принтерами, параметры, драйвер и журнал.
- Параллельная отправка независимых заданий: до 10 одновременно, не более одного задания на конкретный физический принтер.
- Локальная дисковая очередь: Windows может передать следующее задание, пока предыдущие отправляются на физические устройства.
- Round Robin с сохранением позиции между перезапусками.
- Проверка TCP-доступности принтеров и автоматический переход к следующему доступному устройству.
- Детальный мониторинг SNMP v1/v2c: готовность, печать, прогрев, замятие, низкий/отсутствующий тонер, бумага, лотки, крышки, обслуживание и активные события Printer-MIB.
- Уровни расходных материалов, если принтер сообщает значения в Printer-MIB.
- Крупная панель из 10 карточек в сетке 5×2, подробности по двойному щелчку, цветовая индикация со светлой и тёмной темами.
- Список установленных драйверов Windows с выбором драйвера виртуальной очереди.
- Групповое управление принтерами: множественное выделение, удаление, включение и выключение выбранных устройств.
- Настраиваемый порядок принтеров в очереди Round Robin; выбранные строки перемещаются вверх/вниз с сохранением их взаимного порядка.
- Контекстные меню для списка принтеров и текстовых полей; копирование, вставка, вырезание, удаление выделенного и выделение всего. Сочетания Ctrl+C/V/X/A поддерживают русскую и английскую раскладки; также доступны Ctrl+Insert, Shift+Insert и Shift+Delete.
- Сброс настроек приложения к стандартным значениям с сохранением очереди Windows и уже принятых заданий печати.
- Создание/обновление виртуального принтера и TCP/IP-порта из приложения с подтверждением UAC.
- Автоматическое сохранение и восстановление настроек; импорт и экспорт JSON.
- Журнал, счётчики, прогресс передачи и состояние каждого принтера/задания.
- Восстановление ожидающих заданий после перезапуска; задания с неизвестным результатом передачи перемещаются в каталог ручной проверки.
- Встроенные команды Windows PrintManagement вызываются из Python. Отдельных `.ps1`-скриптов для установки или обновления нет.

## Требования

- Windows 10 или Windows 11.
- Python 3.10+ с компонентом **Tk/Tcl** (Tkinter). В установщике Python должен быть включён пункт `tcl/tk and IDLE`.
- На компьютере заранее установлен совместимый драйвер Kyocera.
- Физические принтеры должны принимать RAW TCP-печать. По умолчанию используются адреса `192.168.20.121`–`192.168.20.130`, порт `9100`.
- Для создания/изменения Windows-очереди требуется подтверждение UAC.

Внешние Python-библиотеки не нужны.

## Запуск из исходников

```powershell
cd C:\\Tools\\Print-Round-Robin
python main.py
```

На вкладке **«Принтеры»** можно выделять несколько строк сочетаниями **Ctrl** и **Shift**, затем одной командой удалить выбранные устройства либо включить/выключить их. Для изменения порядка выделите один или несколько принтеров и используйте кнопки **«Выше» / «Ниже»** или **Alt+↑ / Alt+↓**. Порядок используется планировщиком Round Robin; сохраните изменения кнопкой **«Сохранить настройки»**. Изменения списка и порядка доступны только при остановленном ретрансляторе и вступают в силу при следующем запуске.

Драйвер печати выбирается **один раз для виртуальной очереди Windows**. На сетевые устройства ретранслятор отправляет уже подготовленный драйвером RAW-поток. Отдельный драйвер на каждый IP-принтер нельзя применить постфактум без изменения архитектуры (например, перехода на EMF и отдельного рендеринга задания для каждого устройства). Поэтому в текущей RAW-схеме доступен один общий драйвер.

На вкладке **«Драйвер и очередь»** обновите список драйверов, выберите нужный драйвер Kyocera и нажмите **«Настроить виртуальную очередь (UAC)»**. Будут созданы или обновлены:

- виртуальная очередь `Kyocera Round Robin`;
- локальный Standard TCP/IP-порт `KYOCERA_RR_LOCAL`, направленный на `127.0.0.1:9100`.

Затем на вкладке «Мониторинг» нажмите «Запустить». Назначьте виртуальную очередь приложениям и пользователям вместо физических очередей.

### Детальная индикация Kyocera через SNMP

Для аппаратных состояний включите SNMP v1 или v2c в настройках сетевого интерфейса принтера. В приложении откройте **«Параметры» → «Мониторинг состояния принтеров (SNMP)»** и задайте ту же read-community (по умолчанию `public`), UDP-порт 161 и интервал опроса. Приложение отправляет только SNMP GET/GETNEXT-запросы; настройки принтера не изменяются.

Приложение читает стандартные объекты Host Resources MIB (состояние печатающего устройства и битовую маску аппаратных ошибок) и Printer-MIB (таблицу активных предупреждений и сведения о расходных материалах). В зависимости от реализации и конфигурации устройства могут отображаться: печатает/ожидает/прогрев, замятие, мало/нет бумаги, мало/нет тонера, открытая крышка, отсутствующий лоток или расходный материал, заполненный выходной лоток, автономный режим и необходимость обслуживания.

Цвета карточек:
- зелёный — готов, ожидает задания;
- синий — печатает;
- бирюзовый — передача документа с компьютера;
- жёлтый — предупреждение (например, мало бумаги/тонера);
- красный — критическая ошибка (например, замятие, нет бумаги/тонера);
- серый — нет связи;
- фиолетовый — прогрев.

Важные ограничения SNMP:
- SNMP должен быть включён и доступен по UDP/161; неверная community, блокировка UDP или отключённый агент дадут состояние «SNMP не отвечает».
- TCP-доступность и SNMP-доступность показываются отдельно: открытый RAW-порт не доказывает, что принтер готов печатать.
- Набор состояний и уровни тонера зависят от того, какие MIB-объекты и таблицы реализованы прошивкой устройства. Если принтер не сообщает процент тонера, приложение явно показывает отсутствие данных и не вычисляет его самостоятельно.
- SNMP v1/v2c передаёт community без шифрования. Используйте его только в доверенной локальной сети и ограничьте доступ к SNMP по ACL/VLAN, если это возможно.

### Переход с предыдущей версии

Предыдущая версия запускала ретранслятор отдельной задачей планировщика `Kyocera Round Robin Relay`. Она может продолжать занимать `127.0.0.1:9100`. После того как старые задания переданы и очередь предыдущей версии пуста:

1. Откройте вкладку «Драйвер и очередь».
2. Нажмите «Остановить и удалить старый ретранслятор (UAC)» и подтвердите запрос UAC.
3. Запустите ретранслятор из новой программы.

Полностью принятые задания, оставшиеся в прежнем каталоге `%ProgramData%\\KyoceraRoundRobin\\spool`, переносятся в новую локальную очередь при первом запуске. Исходные файлы перемещаются в подпапку `migrated_by_print_round_robin` старого каталога, чтобы не импортировать их повторно.

### Двусторонний обмен

После создания очереди откройте **Свойства принтера → Порты** и снимите флажок **«Разрешить двусторонний обмен данными»**, если он включён. Эта настройка зависит от драйвера и конфигурации Windows, поэтому приложение не меняет её автоматически.

## Настройки и данные

Настройки и журнал пользователя:

```text
%APPDATA%\\PrintRoundRobin\\
    settings.json
    print_round_robin.log
```

Позиция Round Robin и рабочая очередь:

```text
%LOCALAPPDATA%\\PrintRoundRobin\\
    state.json
    spool\\       # принятые задания, ожидающие/передаваемые принтеру
    failed\\      # задания для ручной проверки
```

Сброс настроек выполняется кнопкой **«Сброс настроек»** в верхней панели. Сбрасываются параметры приложения, список и порядок принтеров, SNMP и тема; очередь Windows, журнал и каталоги `spool` / `failed` не удаляются. Автозапуск приложения при входе в Windows отключается.

Настройки сохраняются автоматически по кнопке «Сохранить настройки» и при нормальном закрытии приложения. Поле «RAW-порт по умолчанию для новых принтеров» применяется при добавлении нового устройства; отдельный порт каждого уже добавленного принтера меняется в редакторе принтера. Перед изменением списка принтеров или параметров работающий ретранслятор необходимо остановить и запустить заново.

## Сборка EXE (необязательно)

```powershell
python -m pip install pyinstaller
pyinstaller --noconfirm --clean --onefile --windowed --name PrintRoundRobin main.py
```

Готовый файл будет находиться в `dist\\PrintRoundRobin.exe`. Tkinter входит в стандартную поставку CPython; PyInstaller нужен только для необязательной сборки EXE.

## Как распределяются задания

Каждое TCP-подключение Windows считается отдельным заданием. Сначала весь поток сохраняется локально, затем один из рабочих потоков резервирует следующий свободный принтер по кругу и передаёт ему задание. Один принтер защищён блокировкой от одновременной передачи двух документов, но разные принтеры могут печатать параллельно.

**Важно:** распределяются целые документы, а не отдельные страницы PDF. Одно большое задание уйдёт на один принтер. Для одновременной загрузки всех устройств в очереди должны находиться несколько независимых заданий.

Проверка состояния выполняется по доступности TCP-порта. Она не определяет наличие бумаги, замятия, тонера или другие ошибки механизма принтера. Если порт принимает соединение, но сам принтер не может печатать, это может быть не обнаружено.

Если соединение с принтером обрывается до отправки первого байта, задание возвращается в очередь. Если отправка уже началась и произошла ошибка, задание помещается в `failed` и автоматически не повторяется: принтер мог получить часть или весь документ, поэтому повтор без проверки способен создать дубликат. При аварийном завершении задания с расширением `.sending` также перемещаются в `failed` для ручной проверки.
